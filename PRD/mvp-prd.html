01

Why an Operating System, not a Website

Building this as a single-tenant tutoring website means every future customer (a school, a coaching centre, an independent teacher) needs a rebuild. Building it as an Education Operating System — modular, multi-tenant, API-first, feature-flagged per organization — means TutorWise is simply the first tenant. Every module (courses, assessments, marketplace, messaging) ships as an independently toggleable capability from day one, even though MVP only exposes a subset.

✓ same platform, same codebase — just a different feature-flag set per organization.

05

Organization Management

Every account belongs to an organization (a tutoring business, initially just one: TutorWise). Org admins can create the organization, invite teachers/admins/students, set branding and view an organization dashboard. This is the multi-tenant seam Phase 1's white-labelling builds on.

Non-Functional Requirements

CategoryRequirement
Multi-tenancyEvery table scoped by organization_id; org data never crosses tenant boundary, even in analytics rollups.
API-firstEvery MVP feature exposed via a versioned REST/GraphQL API before the UI consumes it — enables Phase 1 integrations without backend rework.
SecurityRole-based access control, encrypted PII at rest, minors' data governed by NZ Privacy Act 2020 with parental consent for under-16 accounts.
PerformanceCatalog search <300ms p95; dashboard load <2s on 4G.
Availability99.5% uptime SLA for core platform.
ConfigurabilityFeature flags per organization from day one, even if MVP only ships one org.
